# Product

## Register

product

## Users

Developers who use AI coding agents daily (Claude Code, Cursor, GitHub Copilot, Gemini, Cline, Continue). They manage a growing library of skills across multiple agents and need a single source of truth that stays in sync without drift. They are technically fluent and spend most of their time in a terminal or IDE — the desktop app is a periodic management surface, not a primary workspace.

## Product Purpose

Skills Bank keeps a developer's AI agent skill collection synchronized across every agent on their machine using symlinks. It provides a registry browser, install/uninstall flows, GitHub-linked personal registries, and manifest import/export. Success means the user sets it up once and never thinks about it again — their skills are always current everywhere.

## Brand Personality

Precise, functional, developer-native. The app should feel like a well-built developer tool: no decoration for its own sake, dense information done cleanly, controls that behave exactly as expected. Like a good CLI turned into a GUI — capable and direct.

## Anti-references

- Consumer SaaS with cream backgrounds, rounded-everything, and marketing motion
- Pastel productivity apps (Notion-style)
- Overly dark "hacker" UIs with neon gradients
- Dashboard analytics products with metric heroes and big colorful numbers

## Design Principles

1. **Disappear into the task.** The UI earns trust by behaving predictably. No invented affordances for standard interactions.
2. **Density without noise.** Developer tools carry a lot of information. Pack it cleanly — tight spacing within groups, clear separation between them.
3. **State over decoration.** Color, weight, and size signal status and hierarchy — not aesthetics. Every visual difference means something.
4. **Consistency is an affordance.** Same button shapes, same section patterns, same spacing rhythm screen to screen. Familiarity reduces cognitive load.
5. **Respect the user's time.** Labels are short and specific. Actions say what they do. Nothing requires explanation that shouldn't need it.

## Accessibility & Inclusion

WCAG AA minimum. All interactive controls keyboard-accessible. Body text and hint text must meet 4.5:1 contrast ratio — no muted gray copy at small sizes that sacrifices readability for aesthetics. Reduced-motion media query on all transitions.
