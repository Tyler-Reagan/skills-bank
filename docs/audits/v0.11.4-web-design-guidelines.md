# v0.11.4 Web Interface Guidelines audit — deferred items

Audit pass against the [Vercel-labs web interface guidelines][src] over the
v0.11.3 + v0.11.4 user-facing renderer surfaces (Header, BrowseTab,
RegistryFilters, TagFilter dropdown, SkillCard, SkillDetailDrawer,
UpdatesModal, LoginScreen, RepoPickerModal, plus `styles.css` / `theme.css`).

Apply-now findings landed in the companion `polish(v0.11.4):` commit. This
file captures items that need maintainer judgement (visual/UX tradeoff,
larger refactor, or arguable spec interpretation) so they aren't lost.

[src]: https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md

## Deferred — semantic / a11y refactors

### SkillCard.tsx — `<div role="button" tabIndex={0}>` for the whole card
`SkillCard.tsx:91-104`. The card wraps a div in `role="button"` with a
keyDown handler. Guideline says use `<button>` for actions. Migrating is
non-trivial because the card contains interactive children (tag X buttons,
"+ tag" button, inline edit form) — nesting buttons is invalid HTML, so
moving to a `<button>` wrapper would force a structural refactor of the
inner controls (e.g. event-delegation off a sibling overlay, or splitting
the card into a labelled link + a separate action row). Worth a design
pass when we revisit card hover/focus behavior.

### TagFilter.tsx — `<button role="checkbox" aria-checked>`
`TagFilter.tsx:66-73`. The tag list items are `<button>` elements with
`role="checkbox"`. ARIA technically permits this, but screen readers
sometimes read both the implicit button role and the overridden checkbox
role inconsistently. Cleaner option: keep the buttons and use
`aria-pressed` instead of `role="checkbox" aria-checked`, since these are
toggle buttons in practice. Skipped to avoid changing the announced
semantics without confirming on VoiceOver/NVDA.

### Modal focus trapping
`UpdatesModal.tsx`, `RepoPickerModal.tsx`, `SkillDetailDrawer.tsx`. None
of the dialogs trap Tab focus inside the dialog — Tab from the last
control escapes into the background page. `useInitialFocus` lands focus
inside on open and `useFocusReturn` restores it on close, but the cycle
isn't bounded. Fixing requires a small focus-trap hook (or react-focus-lock)
plus careful interaction with the existing Escape-stack. Worthwhile but
deserves its own polish PR.

### Drawer overlay semantics
`SkillDetailDrawer.tsx:444-448`. The drawer overlay is a clickable
`<div aria-hidden="true">` that dismisses the drawer when overlay-ready.
Guidelines flag clickable non-button elements. The pattern is common and
the drawer is keyboard-dismissible via Escape, but a stricter reading
would route this through a `<button>` overlay or a backdrop component
that uses pointer-events without a click handler on a div. Defer.

## Deferred — animation / motion polish

### SkillCard inline `animationDelay` not gated by reduced-motion
`SkillCard.tsx:93`. Each card sets `animationDelay: ${index * 30}ms`
inline. The global `prefers-reduced-motion` rule sets
`animation-duration: 0.001ms` so the animation effectively no-ops, but
the staggered delay still ticks. Effect is imperceptible at 0.001ms
duration. Could clean up by skipping the inline style when the media
query matches (requires `useReducedMotion`-style hook).

### Drawer entrance spring overshoots
`styles.css:1424` — `animation: slideInRight 0.28s cubic-bezier(0.34, 1.2, 0.64, 1)`.
Overshoot is intentional but borderline against the guideline's
"interruptible animations" advice. Acceptable as-is; flagged here so a
future redesign can revisit if a user reports motion discomfort beyond
the reduced-motion fallback.

## Deferred — typography / copy

### Straight quotes in component strings
Several user-facing strings use ASCII apostrophes (e.g. "skill's",
"you've", "can't"). The guideline prefers curly quotes. Touching these
would intersect with the v0.11.4 language sweep already in flight; defer
to that sweep so the canonical-glossary owner can normalize in one pass.

### Tab / mode `Title Case` on header buttons
Buttons mix Title Case ("Update", "Refresh from bank") with
sentence-case-ish labels ("Reveal in Finder", "Forget this skill",
"Pick new location", "Mark as local", "Link origin"). The guideline
prescribes Chicago Title Case for buttons. Many of these labels are part
of the canonical glossary established in v0.11.3; deferring so we don't
re-litigate the verb table inside a polish pass.

### Non-breaking spaces between numerals and units
`SkillCard.tsx`, `SkillDetailDrawer.tsx`: strings like `8 deployments`,
`14 days`, `1.5s` lack `&nbsp;`. Low-risk to apply but mechanical; defer
to the language sweep.

## Deferred — focus styling

### `outline: none` on `.search-bar input` and `.tag-input`
`styles.css:575,1671`. Both set `outline: none` and replace with a
`box-shadow` ring on `:focus` (not `:focus-visible`). Functionally
correct — the shadow ring renders for both click and keyboard. The
guideline prefers `:focus-visible` to suppress the ring on click while
keeping it on keyboard, but for text inputs the "ring on click" is
often desired since the user clicked into the field. Leaving as-is.

### `.info-tooltip:focus-visible { outline: none }`
`styles.css:1066-1068`. The tooltip swaps color on focus instead of
showing an outline ring. Argued OK because the tooltip itself becomes
visible on focus, giving a much stronger affordance than a 2px outline.

## Deferred — i18n / formatting

### Hardcoded `toLocaleDateString()` calls
`SkillDetailDrawer.tsx` uses `new Date(x).toLocaleDateString()` which
honors the user's locale but doesn't pin a format. Guideline prefers
`Intl.DateTimeFormat`. Functionally identical for our use case; defer to
when i18n actually ships.

### No `translate="no"` on brand / code tokens
Brand mark `skills-bank`, skill names, repo names, SHA prefixes —
none are wrapped with `translate="no"`. Low priority for a
desktop-Electron app where browser auto-translate isn't in play, but
worth a pass if we ever ship a web build.

## Notes

The repo already does the right thing in several places that the
guidelines call out:

- Global `prefers-reduced-motion` reset zeros animation/transition
  durations (`styles.css:63-72`).
- `:focus-visible` rings are defined globally with a 2px accent outline
  at +2px offset (`styles.css:50-54`).
- `visually-hidden` helper exists for skip-link-like usage
  (`styles.css:80-90`).
- Header h1 uses `.visually-hidden` so the document outline starts at
  h1 even though the visible brand is a styled div (`Header.tsx:100`).
- Modals/dialogs use `role="dialog" aria-modal="true"` with an
  accessible name via `aria-label`.
- Escape-to-close is implemented as a single document-level capture
  listener with a LIFO stack so nested dialogs unwind correctly
  (`hooks/useEscapeToClose.ts`).
- Skeleton loading state for SKILL.md preview uses
  `role="status" aria-busy="true"` correctly
  (`SkillDetailDrawer.tsx:905-908`).
