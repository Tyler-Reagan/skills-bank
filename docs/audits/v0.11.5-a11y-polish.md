## Deferred (3 milestones, with reasons)

### M2 — SkillCard `<button>` wrapper (D1 from v0.11.4 audit)

**Why deferred.** Currently a `<div role="button" tabIndex={0}>` wrapping nested interactive children — tag X buttons, "+ tag" form, agent chips. Nesting `<button>` elements is invalid HTML, so a real-button migration forces a structural refactor of the inner controls. Two viable paths: (a) event-delegation overlay; (b) split the inner action row out of the activation surface (card-as-link plus separate action row). Either is a design call the maintainer should make — neither belongs in a single commit dropped into a polish pass.

**Re-route.** Schedule as its own focused PR in v0.11.5 follow-up or v0.11.6 (it overlaps the renderer-state-architecture work on App.tsx/component splits).

### M4 — Drawer overlay semantics (D4 from v0.11.4 audit)

**Why deferred.** The drawer overlay is a clickable `<div aria-hidden="true">`. Guidelines flag clickable non-button elements. The pattern is industry-common and the drawer is keyboard-dismissable via Escape (now also focus-trapped inside per M1). The fix would be a `<button>` overlay or a backdrop primitive — both viable, neither a clear win over the current behavior. Defer until a user-facing complaint surfaces.

### M5 — Typography sweep

**Why deferred.** Three sub-items, all mechanical-with-judgement:

- **Curly quotes.** ASCII `'` / `"` throughout user-visible strings should become typographic `’` / `“ ”`. Mechanical, but every replacement needs to be scoped to JSX text + string literals — not code identifiers, not file paths, not URLs.
- **NBSP between numerals and units.** `8 deployments`, `14 days`, `1.5s` → with ` `. Same scoping concern.
- **Chicago Title Case audit on button labels.** Many button labels (`Reveal in Finder`, `Forget this skill`, `Pick new location`, `Mark as local`, `Link origin`) are part of the canonical glossary settled in v0.11.2/v0.11.3. Touching them without re-litigating verbs is the trick.

**Re-route.** Land as a focused commit in v0.11.5 follow-up — subagent-driven sweep is fine but the diff wants human review before merge. Doesn't unblock any later plan.
