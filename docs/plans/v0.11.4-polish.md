# v0.11.4 — Production polish

UI/UX polish and bug-fix release. No paradigm shifts. The cohesive theme: **the app should feel pre-1.0-shippable when used by a maintainer of this repo.** Broken local symlinks heal, the Browse filter strip looks intentional rather than two strips bolted together, the GitHub avatar in the header actually loads, and language across the surfaces matches the canonical glossary.

This plan is structured as a DAG so the work can be fanned out to parallel subagents where safe. Every node lists its dependencies, the files it touches, parallel-safe siblings, and a dispatch-ready agent prompt.

### styles.css contention note

M2 (§b), M3 (§a), and M8 (§c) all live in `styles.css` but in disjoint sections. CSS-section edits at distinct line ranges should merge cleanly — *if* each subagent reads the file fresh before writing. To eliminate the merge-conflict tail, **either**:

1. **Single-batch CSS agent** — one subagent does the M2/M3/M8 CSS edits in one pass, then dispatches M2's TSX edits + M3's TSX edits + M8's TSX edits to separate sub-subagents that don't touch CSS.
2. **Sequence the three** — M3 first (smallest CSS footprint), then M8, then M2 (largest). Each is brief.
3. **Worktree-isolated subagents (default)** — accept that three concurrent worktrees on `styles.css` may produce a 3-way merge that needs manual reconciliation. With section-isolated edits, conflicts should be rare; budget ~5 minutes of cleanup if they happen.

Recommendation: **option 3 with worktrees** unless we hit a conflict, then fall back to option 2.

## Conflict audit

- **M2 vs M4.** Hard sequence required — M2 settles chip markup, M4 then renames labels in stable structure. Reverse order means M4 edits text that M2 immediately restructures.
- **M4 vs M5.** Hard sequence required — M5 deletes truly-unused exports; M4's renames may newly-orphan exports that knip should then catch. Running M5 first means M4's rename re-introduces references that M5 just deleted, and the rename leaves the same export newly-unused.
- **M6a vs M6b.** M6a runs query-only; M6b runs after user approval of which discovered skills to apply.
- **M7 vs M9.** Different scripts in `scripts/`. Independent. Worktree-safe.
- **M1 vs everything else.** M1 touches no `src/` files. No conflict with any code change. Pre-merge it can land in any order.
- **M8 vs M2.** Disjoint CSS sections + disjoint TSX files. Safe in parallel under the worktree caveat above.

### M1 — Local-state heal

**Symptoms observed on `feat/v0.11.4-polish` HEAD~0:**

```
 M skills/vendored/react-components/.skills-bank.json
 D skills/vendored/react-components/meta.json
 M skills/vendored/ubiquitous-language/.skills-bank.json
 D skills/vendored/ubiquitous-language/meta.json
```

Plus the v0.11.4-install subagent found **every pre-existing symlink** under `~/.claude/skills/` for the six newly-installed skills was dangling (pointed at the pre-split path). This is likely true for other skills too — broader sweep needed.

**Steps:**

1. Audit `~/.claude/skills/` and `~/.cursor/skills/` for every symlink whose target doesn't resolve. Repoint to the post-split `skills/<bucket>/<name>/` location.
2. Triage the working-tree marker churn — decide whether the `.skills-bank.json` diffs are legitimate post-migration baselines (commit them) or runtime side-effects the app keeps emitting (revert + file the bug separately).
3. For the orphaned `meta.json` deletes: confirm `pnpm build:index` is clean either way, then either commit the deletions or restore the files.
4. Document the maintainer-flow heal sequence in `CLAUDE.md` so future maintainers don't re-derive it.

**Subagent dispatch:** safe — research + heal, no source code. See `scripts/sweep-broken-symlinks.ts` if it exists; otherwise the agent writes a one-shot bash sweep.

### M2 — Standardize the Registry filter strip

**Current state:** `RegistryFilters` (v0.11.3) renders chips + sort in one strip. `BrowseTab.tsx` renders `Installed only` + `TagFilter` in a separate `.filter-row` below it. Two strips of different sizes and weights.

**Targets:** single visual row with uniform chip metrics, label casing, and count rendering. Sort buttons keep right-aligned position but match chip metrics. TagFilter integrates as a "Tags ▾" dropdown chip (preferred — tags are open-ended) or as inline chips for selected tags only.

**Open decision:** "Installed only" in the chip strip or elsewhere? Lean: in the strip.

**Subagent dispatch:** safe with the `styles.css` caveat. The chip-styles section in `styles.css` is `~ lines 850-940`. Touches: `BrowseTab.tsx`, `RegistryFilters.tsx`, `TagFilter.tsx`, `styles.css` §b.

### M4 — Language sweep

**Inputs:** `UBIQUITOUS_LANGUAGE.md` + every `*.tsx` under `packages/desktop/src/renderer/` + the README.

**Process:** run `Skill(naming-analyzer)` and `Skill(ubiquitous-language)` against the renderer surface. Accept changes aligned with the canonical paradigm (Origin = authoritative upstream, bundled = curation layer); defer/reject ones that drift.

**Out of scope:** renaming internal capability flags or core schema types — those carry semantic weight. Limit to user-visible copy unless a glossary entry explicitly demands an internal rename.

**Subagent dispatch:** **don't dispatch as a raw general-purpose agent**. Instead, invoke the named skills directly via `Skill(naming-analyzer)` and `Skill(ubiquitous-language)` in the main session so their structured output goes through normal review. M4's diff surface is too broad to delegate blindly.

**Context:** when upstream lacks `meta.json`, the resulting vendored skill folder has only `SKILL.md`. `pnpm build:index` synthesizes the registry entry from frontmatter, but the per-skill `meta.json` that the rest of the codebase assumes is absent.

**Subagent dispatch:** safe. Touches: `scripts/vendor-skill.ts` + adjacent lib helpers if any.

**Context:** v0.11.3 PR #40 added `.skill-card--update-available` as a 2px left accent border. impeccable flags any side-stripe >1px. The original justification (the in-card UPDATE badge carries the primary signal; the stripe is grouping affordance) holds, but a fresh-eye comparison should pick between: 2px stripe, 1px stripe, or a corner chevron icon.

**Subagent dispatch:** partial — needs a UX call. Best path: invoke `Skill(impeccable)` directly, ask it to render the three variants, user picks.

### M9 — Bucket-default fix for maintainer tooling

**Context:** `vendor:skill` writes `source: "bundled"` (landed in PR #38). The orphaned cases are `stamp:self-authored` and `discover:bundled --apply`, which rely on `readSkillSource`'s default of `"yours"` — wrong for skills the maintainer is intentionally adding to the bundled set.

**Scope:** default newly-stamped markers from those two scripts to `source: "bundled"`. Add a `--source yours` opt-out flag for the rare case where the default is wrong.

**Subagent dispatch:** safe. Touches: `scripts/stamp-self-authored.ts`, `scripts/discover-bundled.ts`.
