# Main-process inventory

Reference inventory of `src/main/` plus the IPC contract it shares with the
renderer (`src/shared/ipc.ts`). What each module does and who consumes it.
Repo-internal — not published to the docs site.

> **Freshness: accurate as of branch `feat/skill-provenance-model` (issue #159,
> origin-only provenance model, ADR-0020/0021).**
> LOC are snapshots; re-verify (`wc -l`) and re-stamp when the main process
> changes materially — or distrust the numbers and trust only the purposes,
> which drift slower.

## Standing observations

- **`main.ts`** (204L): boot and lifecycle only after the v1.23.0 IPC split.
  Domain growth goes into the relevant `ipc-*.ts` file; `main.ts` should not
  grow past registering handlers and wiring lifecycle.
- **`ipc-registry.ts`** (942L): the largest domain file. If a distinct sub-domain
  within the registry (e.g. skill-content editing, label management) accumulates
  enough handlers to be coherent on its own, that's the first split candidate.
- **`ipc-manifest.ts`** (727L): the export/import/push/pull surface. Shrank
  materially in the v6 migration (issue #159) once the curated-tarball-sync
  subsystem was deleted.
- **`shared/ipc.ts`** (922L): grows linearly with the channel count; split by
  domain only if a consumer ever needs a strict subset (today all three consumers
  want the whole contract).
- **No more circular-import shim**: `replaceRegistryWithRepo` (in `ipc-repos.ts`)
  is no longer consumed by `ipc-manifest.ts` — both now drive the same
  `fetchRemoteManifest` + `reconcileRegistryToManifest` engine independently, so
  the `setReplaceRegistryWithRepo` setter-injection pattern from `main.ts` is gone.
